工具调用失败。仔细阅读错误信息并修复具体问题。

## 失败调用详情：
- 工具：$tool
- 错误：$error
$original_args_section
$available_actions_section

## 修复方法：
1. 阅读上面的错误信息——它告诉你具体哪里出了问题。
2. 如果错误说"Unknown action"或"invalid action"，检查工具 schema 中的有效 action 列表。
3. 如果错误说参数缺失或参数名错误，检查工具 schema 中的正确参数名。
4. 绝不要用相同参数重试——相同参数会产生相同错误。
5. 修复错误信息指出的具体问题，然后重试。
6. 修复错误后，继续当前计划步骤，除非这个错误已经证明该步骤被阻塞。
7. 不要因为这一次工具调用失败就切换实现路径。
8. 如果错误信息包含 "deny"、"network"、"Permission denied"、"sandbox"、"socket.gaierror"、"Errno 8"、"ConnectionError"、"URLError"、"NewConnectionError"、"nodename nor servname" 或 "getaddrinfo failed" 等关键词，这很可能是沙箱网络限制——不要重试，系统会提示用户审批网络访问，等待用户批准即可。
9. 当任务仍有剩余工作时，不要把这次失败变成一个仅包含状态的总结。
10. 修复工具调用问题后，回到同一个任务目标继续执行。

## Doom Loop 预警（死循环检测）：

系统会自动检测**连续 3 次相同工具+相同参数**的调用模式。一旦触发，你会收到明确的 "Doom Loop Detected" 提示。

**什么是 Doom Loop？**
- 连续 3 次用**完全相同的工具名+参数**调用，却没有推进任务
- 例：`grep "config"` 失败 → 微调成 `grep "Config"` 失败 → 再微调成 `grep "CONFIG"` 失败
- 本质：在参数空间里打转，但思路没变

**如何避免？**
1. **第一次失败**：仔细读错误信息，修复具体问题（如参数名错误、路径错误）
2. **第二次失败**：如果同样的修复思路不奏效，说明方向可能错了
3. **换工具或换思路**：
   - `grep` 找不到 → 用 `glob` 看目录结构，或 `file` 列文件树
   - 文件读取失败 → 先确认路径是否存在
   - 某个 API 参数一直报错 → 读工具 schema 或相关文档
4. **标记阻塞**：如果尝试了不同工具/思路仍然失败，调用 `plan` 工具标记当前步骤为 `blocked`，说明阻塞原因

**核心原则**：微调参数≠换方法。连续失败时，必须跳出当前工具的参数空间，换一个观察角度。
