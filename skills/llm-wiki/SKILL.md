# LLM-Wiki 多知识库助手

## 这是什么

把 LLM 当作**知识编译器**：将散装资料增量编译成持久化、互相关联的 Markdown wiki，
替代"每次从头检索"的一次性 RAG。知识以普通 Markdown 文件沉淀在磁盘上，
可阅读、可 git 管理、越用越厚——**使用即积累**。

核心循环四步：**摄入（Ingest）→ 查询（Query）→ 归档（File Back）→ 自检（Lint）**。

## 多知识库约定

不同主题的知识放在**相互隔离的库**里，默认不跨库操作：

```
<工作区>/wikis/
├── <库名A>/
│   ├── wiki.yml      # 库元数据：name / description / created_at
│   ├── raw/          # 摄入区：待编译的原始资料
│   │   └── processed/  # 已编译资料的归档（保留溯源）
│   ├── pages/        # 编译产物：互相关联的主题页面（.md）
│   └── index.md      # 全库索引：页面清单 + 一句话摘要，查询的入口
└── <库名B>/
    └── ...
```

**重要边界**：只在 `wikis/` 目录内读写，不碰工作区其他文件。
跨库查询只在用户明确要求时做（逐库分别查再综合），日常操作严格单库。

## 库管理

开始任何知识库操作前，先确定操作目标库：

- **列库**：扫描 `wikis/` 下各库的 `wiki.yml`，列出名称与描述。
- **建库**：用户给库名和用途后，创建上述目录结构，`wiki.yml` 写入
  `name` / `description` / `created_at`，`index.md` 初始化为空索引模板。
- **选库**：用户说"用 XX 库"或在上下文中明确；不明确且只有一个库时默认用它，
  多个库时**先问用户**，不要擅自猜。

## 四步循环

### 1. 摄入（Ingest）

触发：用户丢来文章/笔记/链接内容，说"存进知识库""消化一下"。

1. 把原始资料存入 `raw/`（保持原样，文件名带日期：`2026-10-03-标题.md`）。
2. 通读资料，提取**可沉淀的事实与概念**（不是照抄全文）。
3. 决定归属：**一个事实只属于一个页面**——已有关联页面就更新它，
   没有就在 `pages/` 新建页面。页面向来以主题命名（如 `mvcc-机制.md`）。
4. 新事实写进页面时，顺手建立与其他页面的**双向链接**。
5. 更新 `index.md`（新增/修订页面的一行摘要）。
6. 把 `raw/` 里的原件移入 `raw/processed/`。
7. 汇报：新建了哪些页面、更新了哪些页面、链接了哪些关系。

### 2. 查询（Query）

触发：用户向知识库提问。

1. 先读 `index.md`，按摘要选出候选页面（通常 1-5 个）。
2. 只读候选页面正文；页面里的链接指向强相关内容时可跟进一跳。
3. 综合回答，**注明答案来自哪些页面**。
4. 索引和页面里都没有的，如实说"知识库里没有"，不要编造。

### 3. 归档（File Back）

触发：一次问答产生了知识库里没有、且值得保留的内容（用户说"这个存一下"，
或回答质量明显值得沉淀时主动提议）。

1. 判断内容归属：并入既有页面，或新建页面。
2. 写入并建立链接，更新 `index.md`。
3. 告诉用户存到了哪个页面——**探索即积累**，这是飞轮的核心。

### 4. 自检（Lint）

触发：用户说"检查一下知识库"，或库明显变大后主动提议。

逐库检查并报告（只报告不自动改，改前经用户确认）：

- **孤立页面**：没有任何其他页面链接进来的页面。
- **断链**：页面里的链接指向不存在的文件。
- **矛盾**：同一事实在两个页面说法冲突，列出两处原文。
- **索引漂移**：`pages/` 有而 `index.md` 未收、或索引里有而页面已删。
- **过时**：带明确日期/版本的信息明显陈旧（如"最新版是 X"但已过时）。

## 页面写作规范

- 一页一个主题，标题即主题名；开头一两句给出"这是什么"的定义。
- 事实与观点分开：事实写清来源（哪篇 raw、哪个日期），推测和判断明确标注。
- 链接用相对路径 Markdown 链接（如 `[MVCC](mvcc-机制.md)`），保证 lint 可检查。
- 规模参考：单库 ~100 页 / 40 万字以内纯索引即可良好工作；
  接近这个量级时建议按主题**拆库**，而不是引入向量检索等重基建。

## 反模式（不要做的事）

- ❌ 把原文整篇复制进页面——页面是**提炼后的知识**，raw/ 才存原文。
- ❌ 一个事实写进多个页面——重复必然腐化，改一处漏一处。
- ❌ 跳过 index.md 直接全域 grep 页面正文——索引是查询入口，保持它权威。
- ❌ lint 时自动删除/合并页面——报告问题，让用户拍板。
- ❌ 未经用户明确就在多个库之间搬运或合并内容。
