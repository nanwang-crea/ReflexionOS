# 事件地图活性保障

防止 `docs/event-map.md`（见 [执行层事件机制](执行层事件机制.md)）腐化的自动化机制，实现在 `backend/tests/test_execution/test_event_map.py`。

**双向比对**：① 用 `ast` 扫描 `app/execution/`、`app/agents/` 下所有 `emit("...")` / `_emit("...")` 调用的首个字符串字面量参数，得到代码中的事件集合；② 从事件地图表格首列的反引号提取已登记集合；③ 代码有而文档无 → 漏登记，测试失败；文档有而代码无 → 腐化条目，也失败。

**两个设计决策**：刻意用 AST 而非全文正则——prompt 文本里形如 `"a:b"` 的字符串不是事件，只有 emit 调用首参才算；emit 首参必须是字面量（f-string/变量会直接报错），否则事件名无法静态提取。

**有效性经过负向验证**：M-02 临时放置含 `_emit("test:fake")` 的文件被成功拦截；M-03 临时向文档追加 `ghost:event` 行也被成功拦截。测试设施必须自证"拦得住坏人"，仅正向通过不算数。
