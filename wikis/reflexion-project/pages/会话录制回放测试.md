# 会话录制回放测试

ReflexionOS 的会话级回归测试设施（2026-10-02 落地）：**把 LLM 响应预录成夹具，测试时用假模型按序播放，驱动真实主循环跑完整任务，断言事件序列与终态**——全程无需 API key。对标 DeepSeek Harness 的 `test:snapshot`。

**四个组件**（全部在 `backend/tests/support/`，业务代码零改动）：

- `replay_fixture.py`：夹具模型（pydantic），JSON 存于 `tests/fixtures/replay/`。每条响应带 `method` 标记（complete/stream）。
- `replay_llm.py`（ReplayLLM）：假模型适配器，按序播放；校验实际调用方法与 `method` 一致（抓"主循环换调用入口"的漂移）；`assert_fully_consumed` 强制调用次数与录制恰好相等。
- `replay_harness.py`：组装真实 `RapidExecutionLoop` + 事件捕获；归一化 = 连续同类事件折叠；断言失败给第一个分叉下标与上下文。
- `recording_llm.py`（RecordingLLM）：包装真实适配器透传并录制，供持 key 者用 `backend/scripts/record_replay_fixture.py` 重录。

**基线纪律**：预期事件序列必须先从状态机源码推导、再与实际运行比对（推导即人工核对），禁止照抄未核对的实际输出——否则错误行为会被固化成基线。首批 3 场景（纯问答/只读工具调用/工具异常恢复）的推导首跑即全中。

断言的事件序列契约见 [执行层事件机制](执行层事件机制.md)；实现期踩过的关键坑见 [生成器提前关闭陷阱](生成器提前关闭陷阱.md)。
