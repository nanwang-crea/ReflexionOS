# 生成器提前关闭陷阱

Python 异步生成器中，**`yield` 之后的代码在消费方提前关闭（`aclose()`）时不会执行**——`GeneratorExit` 从 yield 点抛入，后续逻辑被跳过。

**实例**（[会话录制回放测试](会话录制回放测试.md) 实现期真 bug）：`stream_collect` 消费流式响应时，拿到终止块（tool_calls/done）即 `break` 并在 `finally` 中 `aclose()` 生成器。RecordingLLM 最初把"聚合落一条录制"写在 `yield 终止块` 之后——消费方一关闭，录制永远落不下来。

**对策**：副作用（录制、清理、提交）必须放在 `yield` **之前**完成，yield 只负责把数据递出去。凡写"边透传边记录"的生成器包装器，都要检查这条时序。
