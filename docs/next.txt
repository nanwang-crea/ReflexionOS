三种实现方案对比
方案 A：最小可行版 — Chat Tab + Code Tab 全屏切换（目前在做，后续要升级到方案C）
- 顶部两个 tab：Chat / Code，点击切换全屏视图
- Code 视图内：上方 Diff / Edit 子 tab 切换，下方 Monaco Editor
- 点击 receipt：自动切到 Code tab 并展示该文件 diff
- 数据流：点击 receipt 时从后端读取文件当前内容，diff 数据来自 payloadJson 中的 patch 文本
- 编辑后：保存按钮调用后端 file/write API
- 优点：实现最简单，和现有布局改动最小，tab 模式直觉清晰
- 缺点：切换视图时聊天上下文完全不可见
方案 B：右侧可收起侧面板 + Chat 区收窄
- 聊天区右侧打开一个可收起的面板（类似 Cursor）
- 面板内 Monaco Editor，Diff / Edit 切换
- 点击 receipt 时面板自动展开
- 优点：聊天和代码同时可见，更接近 Cursor 体验
- 缺点：聊天区收窄后长内容体验差，布局响应式复杂，实现成本中等
方案 C：全屏 Code 视图 + 左侧变更文件列表
- Code 视图左侧列出本会话中被修改过的所有文件
- 右侧 Monaco Editor 显示选中文件的 diff 或编辑视图
- 优点：会话维度的变更总览，更适合多文件改动场景
- 缺点：复杂度最高，需要维护变更文件列表的状态，超出了"单文件视图"的需求范围
